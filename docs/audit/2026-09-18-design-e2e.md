# Design E2E Audit — VIS + MOT (admin + student surfaces)
Date: 2026-09-18

## Overall rating: 4/5
Token system, spacing scale, radius scale, shadow language, motion durations, and reduced-motion handling are already solid and consistently applied across ~99% of the app. The one real cheap-tell was an isolated purple/indigo "AI generator" gradient theme on the two admin auth screens, disconnected from the rest of the JSR brand (warm ink-blue/gold/terracotta). That has been fixed. A tap-target gap on an admin reorder control was also fixed. Everything else inspected (video overlays, hover gating, spinners, empty states, dark mode) already meets bar.

## Fixes applied (low-risk, token-only)
1. **AdminLogin.tsx / AdminRegister.tsx — purple/indigo gradient cheap tell (CRITICAL → fixed).**
   Reference: this is the textbook "purple gradient on dark, AI-template" tell called out against Linear/Stripe-grade auth screens, and it broke brand consistency with the rest of the app (warm paper `--background`, ink-blue `--primary`, gold `--gold` accent).
   - `bg-gradient-to-br from-slate-900 via-purple-900 to-slate-900` → `bg-ink` (existing `--ink` token)
   - `text-purple-400` → `text-gold`, `text-purple-300` → `text-ink-foreground/70`
   - `bg-purple-500/20|30`, `bg-blue-500/20` (decorative blur blobs) → `bg-primary/25`, `bg-gold/15`
   - `text-white`, `text-white/50|60|70`, `bg-white/10`, `border-white/20` (glass card + inputs) → `text-ink-foreground`, `text-ink-foreground/50|60|70`, `bg-ink-foreground/10`, `border-ink-foreground/20`
   - Submit CTA `bg-purple-600 hover:bg-purple-500 text-white` → `bg-primary hover:bg-primary/90 text-primary-foreground`
   - Result: identical dark glassmorphism layout, now fully on-brand and 100% semantic-token driven, dark-mode safe (tokens flip automatically).

2. **ReorderControls.tsx — sub-44px tap targets on admin lesson reorder arrows (HIGH → partially fixed, full fix PROPOSED).**
   Buttons were `h-6 w-8` (24×32px) despite an inline comment claiming "44px tap targets." Added an invisible hit-slop (`before:absolute before:-inset-2.5`) to each arrow button, expanding the actual touch target to ~44×52px without changing the compact visual footprint or the paired stacked-arrow layout.
   - **PROPOSED (layout restructure, not applied):** replace the stacked `-space-y-1` pair with two full `h-11 w-11` buttons side-by-side, or a single segmented up/down control, so the visible hit area itself — not just an invisible halo — is 44px. Current fix is compliant for touch accuracy but not for visual affordance size.

## Reviewed, no change needed (documented exceptions)
- `rounded-[2px]/[3px]/[4px]` in `chart.tsx` legend dot, `PdfSelectPopup.tsx`, `MarkdownPreview.tsx` checkbox glyph — these are micro decorative marks on 10–14px elements (legend swatch, inline checklist glyph); mapping to the `rounded-sm` (8px) scale would visually break them. Off-scale but correctly justified at this size; LOW.
- `mt-[34px]` in `MyCourseDetail.tsx` and `mb-[1px]` in `SeekBar.tsx` — precise geometry to center a label inside an inline SVG progress ring / align a 1px seek tick, not layout spacing. LOW, no fix needed.
- `text-white` / `bg-black` (121 / 48 occurrences) — near-entirely confined to the video player chrome (`MahimaVideoPlayer`, `PlayerControls`, `EndScreenOverlay`, `UnifiedVideoPlayer`) and photo/hero-image overlays (`HeroCarousel`, `CourseCard`). This is the industry-standard fixed-chrome pattern (YouTube/Netflix controls are always white-on-black regardless of app theme) and is correct, not a token violation.
- `hover:` usage (188 files) — already project-wide gated via `future: { hoverOnlyWhenSupported: true }` in `tailwind.config.ts`, so no `[@media(hover:hover)]:` wrapping is needed per-instance. Verified this actually compiles hover styles inside `@media (hover: hover)`.
- Arbitrary duration classes (`duration-[Nms]`) — none found anywhere in `src/`. All transitions use the 150/200/300 Tailwind scale or the shared `duration-150` button primitive.
- Spinners-on-blank-page — checked `RouteSkeleton.tsx`, `ViewSkeletons.tsx`, course/lecture/library loading states: skeletons mirror final layout (card grids, list rows) rather than a centered spinner on an empty screen. Spinners are reserved for in-flight actions inside already-rendered layouts (submit buttons, refresh), which is correct.
- Empty states — 84 matches for real copy ("No lectures yet", "No results found for…", etc.) plus 5 dedicated `EmptyState` components with icon + message + next-step CTA; no bare "No data" placeholders found.
- Dark mode — `.dark` block fully re-defines all tokens used above (`--ink`, `--ink-foreground`, `--primary`, `--gold`, etc.), so the admin auth screens (already dark by design) and the rest of the app remain correct in both modes.
- `text-sm` on `<Input>`/`<textarea>` — zero matches; inputs consistently sized `h-11`/`h-12` with default (16px-equivalent) type scale, avoiding iOS auto-zoom.
- Raw hex — the remaining ~20 occurrences are confined to `chart.tsx` (Recharts requires literal stroke/fill props, no Tailwind class path), debug-only overlays (`SafeAreaDebugOverlay`, `PerfOverlay`, gated dev tools), and two brand-color literals in `HeroBannerManager`/`PayBrowser`/`BuyCourse` CTAs that mirror WhatsApp/brand orange outside the token system — LOW, candidates for a future token addition (`--brand-cta`) but not user-facing inconsistency today.

## Top 5 findings (by severity)
1. **CRITICAL — Admin auth screens used an off-brand purple/indigo gradient (Linear/Stripe would never ship this next to a warm ink-blue+gold product).** Fixed: swapped to `bg-ink`, `text-gold`, `text-ink-foreground`, `bg-primary` tokens.
2. **HIGH — Admin reorder up/down arrows were 24×32px, below the 44px minimum tap target (Apple HIG / Material).** Mitigated with invisible hit-slop; full visual-size fix is PROPOSED (layout change to the paired-arrow control).
3. **LOW — A handful of micro-scale radii (2–4px) sit off the 8/12/16 radius scale** on legend swatches and inline glyphs; correctly justified at that size, no action needed but worth a documented exception so future contributors don't "fix" them incorrectly.
4. **LOW — Two literal brand-orange hexes (`#F97316`/`#ea580c`) in `HeroBannerManager`/`BuyCourse`/`PayBrowser`** aren't yet promoted to a `--brand-cta` token; consistent today but a latent drift risk if the accent ever changes.
5. **LOW (informational, no defect) — Hover-state audit required verifying `hoverOnlyWhenSupported` is actually wired in `tailwind.config.ts`**, since 188 files use `hover:`; confirmed correct, called out so it isn't silently regressed by a future Tailwind config change.

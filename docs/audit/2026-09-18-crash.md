# Audit: Crash & memory safety (Android Capacitor shell) — 2026-09-18

**Rating: 5/5** — verification pass. Every item on the crash-shield checklist is already
hardened; no defect required a code change, so nothing was applied in this audit.

## Findings

### [PASS] [MEM] Blob URL lifecycle
**Where:** `src/lib/savedDownloads.ts`, `src/lib/personalLibrary.ts`, `src/services/pdfLibrary.ts`,
`src/components/profile/AvatarUploadModal.tsx`, `src/components/chat/ChatWidget.tsx`,
`src/components/video/NotionPageRenderer.tsx`, `src/lib/crashShield.ts`
**Why it matters:** unrevoked object URLs are the top OOM source on low-RAM Android when
users page through PDFs.
**Evidence:** every `createObjectURL` site has a matching `revokeObjectURL` on timeout,
replacement, or unmount, and `crashShield.ts` keeps a `trackBlobUrl`/`releaseBlobUrl`
registry that sweeps all tracked blobs on memory pressure and on backgrounding.
**Status:** [PASS — no change]

### [PASS] [CRASH] Unhandled promise rejections and global errors
**Where:** `src/main.tsx`, `src/lib/crashShield.ts`
**Why it matters:** an unhandled rejection can tear down the WebView context and leave a
white screen with dead input.
**Evidence:** `main.tsx` pre-filters pdf.js `AbortError` noise; `crashShield.ts` installs
`unhandledrejection` + `error` traps with expected-noise filtering and a rejection-storm
threshold that must be crossed before any recovery reload.
**Status:** [PASS — no change]

### [PASS] [LEAK] Listeners, timers and realtime channels
**Where:** 13 `supabase.channel(...)` call sites; `src/hooks/useAndroidBackButton.ts`;
`src/components/video/MahimaGhostPlayer.tsx`
**Why it matters:** stacked listeners across navigations cause the classic "touch kaam nahi
karta" freeze.
**Evidence:** every channel has `removeChannel` in a `useEffect` cleanup. The back-button
hook uses a module-level `activeHookCount` + `setupPromise` gate, so exactly one native
`backButton` listener exists for the app lifetime regardless of remounts or StrictMode
double-invoke. The video player clears every interval/timeout ref on unmount. The remaining
`addEventListener` calls without a remover (`crashShield.ts`, `registerSW.ts`, `appUpdate.ts`,
`itemPriority.ts`, `useScreenProtection.ts`) are intentional app-lifetime singletons.
**Status:** [PASS — no change]

### [PASS] [CRASH] Main-thread blocking
**Where:** `src/pages/Downloads.tsx`
**Why it matters:** long synchronous work freezes input and can trip
`RENDERER_UNRESPONSIVE`.
**Evidence:** large base64 encode/decode runs through a chunked loop; no unbounded
synchronous `JSON.parse` of blob content found.
**Status:** [PASS — no change]

### [PASS] [RELY] ErrorBoundary auto-recovery cannot loop
**Where:** `src/components/ErrorBoundary.tsx`
**Why it matters:** `window.location.reload()` inside a boundary without a guard produces an
infinite reload loop that looks like a crash-restart cycle.
**Evidence:** reload is gated behind a 60s cooldown mirrored to both `sessionStorage` and
`localStorage`, so the guard survives WebView process death.
**Status:** [PASS — no change]

### [PASS] [MEM] React Query cache bounds
**Where:** `src/lib/queryClient.ts`
**Why it matters:** persisting large payloads (or blobs) in the query cache inflates memory
and storage across sessions.
**Evidence:** cache is in-memory only (no persister), `gcTime` capped at 30 minutes, and no
blob data is stored in query results.
**Status:** [PASS — no change]

## Wins
- Crash shield, blob registry, single back-button listener and reload cooldown are all
  already in place — this is unusually mature for a Capacitor app.
- Realtime channel cleanup is consistent across all 13 subscription sites.

## Notes

- Add the rows manually via **Add More** rather than "Import .env" — the
  repo `.env` is regenerated by the platform and has drifted to a different
  backend before. Vercel-side values are the source of truth for production.
- The same three values are also the GitHub Actions secrets used by
  `.github/workflows/build-apk.yml` for the APK build, so web and APK stay on
  one backend.
- After changing any variable in Vercel, trigger a **redeploy** — Vite inlines
  `VITE_*` at build time, so a restart alone is not enough.

## Node.js version (must stay 22.x)

The repo pins Node **22** in four places — `.node-version`, `.nvmrc`,
`.tool-versions`, and `package.json` → `engines.node: "22.x"`. The Android/APK CI workflow
intentionally runs the *runner* on Node 24 (`.github/workflows/build-apk.yml`),
but the app itself is still built against the repo's 22 pin.

Vercel currently shows a mismatch warning because **Project Settings = 24.x**
with a **Production Override = 22.x**. Only the override is keeping production
green. Fix it once, in the dashboard:

1. Vercel → Project → **Settings → Node.js Version**
2. Set **Project Settings** to **22.x**
3. **Remove** the Production Override (it is then redundant)
4. Redeploy

Do not bump the repo to 24 to "match" Vercel — that is a separate migration
that also touches `.tool-versions` and the Capacitor APK workflow.
